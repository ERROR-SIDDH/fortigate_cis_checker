FortiGate CIS Compliance Checker

A small Python tool that connects to a FortiGate firewall, reads its configuration and compares it with hardening controls taken from the CIS FortiGate 7.x Benchmark. It does not change anything on the firewall.

  • Source on GitHub
  • Sample HTML report
  • Device setup guide

This is a coursework project. It is not an official CIS-CAT tool and does not contain any CIS benchmark text.

Why

A FortiGate in its factory configuration works, but it does not meet the CIS baseline. HTTP management is enabled, USB auto-install is on, no login banner is shown and logs stay on the box. Checking all of this by hand is slow and easy to get wrong. This tool checks it in under a second and lists the exact CLI commands that fix each finding.

How it works

  1. The tool logs in to the FortiOS REST API with a token that belongs to a read-only API user. SSH is also supported.
  2. It downloads the configuration tables it needs, such as system/global, system/interface, system/password-policy and log.syslogd/setting.
  3. It runs each rule against that data. Each result is PASS, FAIL, WARN or ERROR, and records the expected value, the actual value and a fix.
  4. It writes the results to the console, a CSV file and a standalone HTML report.

Read-only by design

There are two separate safeguards against writes, and either one is enough on its own:

  • In the client. The REST client only sends GET requests. The SSH client refuses any command that is not get, show or diagnose sys.
  • On the device. The API user uses an access profile with every permission group set to read, and its trusthost only allows the scanner's IP. The FortiGate rejects writes even if the script is modified.

Install

git clone https://github.com/ERROR-SIDDH/fortigate_cis_checker.git
cd fortigate_cis_checker
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

Prepare the FortiGate

Do this once, as a full admin, from the FortiGate CLI. Replace <scanner-ip> with the IP address of the machine that will run the checker.

config system accprofile
    edit "cis_readonly"
        set sysgrp read
        set netgrp read
        set loggrp read
        set fwgrp read
        set authgrp read
        set secfabgrp read
        set ftviewgrp read
        set vpngrp read
        set utmgrp read
        set wanoptgrp read
        set wifi read
    next
end

config system api-user
    edit "cis_checker_api"
        set accprofile "cis_readonly"
        set vdom "root"
        config trusthost
            edit 1
                set ipv4-trusthost <scanner-ip> 255.255.255.255
            next
        end
    next
end

execute api-user generate-key cis_checker_api

Run the last command from the top-level # prompt. If you run it from inside a config block, FortiOS replies Unknown action 0. FortiOS shows the token only once, so copy it straight away.

Run

export FGT_API_TOKEN="<token>"
python3 main.py --backend api --host 172.20.80.130 --insecure \
    --csv reports/report.csv --html reports/report.html

--insecure turns off TLS verification for the factory self-signed certificate. Use it only in a lab. The exit code is 0 when every check passes, 1 when any check fails and 2 when the tool cannot connect.

Fixing the failures

config system password-policy
    set minimum-length 14
end
config system interface
    edit "port1"
        set allowaccess https ssh ping
    next
end
config system global
    set pre-login-banner enable
end
config system auto-install
    set auto-install-config disable
    set auto-install-image disable
end
config log syslogd setting
    set status enable
    set server <syslog-server-ip>
end

Run the checker again afterwards to confirm that the score has gone up.

Limitations

  • The tool covers 11 controls, not the full benchmark. Adding a control means writing one function in rules.py.
  • The rule IDs are this project's own. To match them with an official CIS PDF, look up each control in the specific benchmark version you are citing.
  • It has been tested against a single FortiGate VM. Table names in the REST API can differ between FortiOS versions.
